# OctoAcme Project Management Docs

This README centralizes OctoAcme's project management process documentation and provides quick links to the docs in the docs/ folder. It’s intended as a single discoverable index for team members and new hires so they can quickly find process guidance, templates, and role definitions.

OctoAcme follows a lightweight, stage-gated lifecycle: Initiation (validate problem and success metrics with a one‑pager), Planning (kickoff, prioritized backlog, estimates, and Definition of Done), Execution (sprints/iterations tracked on a project board and small PRs with linked issues), Release (checklist-driven deployments with rollback plans), and Close/Retrospective (capture learnings and assign action items). The workflow emphasizes iterative delivery, clear ownership, and data-informed decisions.

Core roles are explicit and accountable: Project Manager coordinates delivery, risks, and communications; Product Manager (PdM) owns outcomes and prioritization; Developers implement and test; QA validates acceptance; and Stakeholders provide inputs and approvals. These roles map to artifacts such as the one‑pager, risk register, release notes, and retrospective action items.

Quality and communication are integrated into the rhythm: daily standups, weekly delivery syncs, regular demos, and monthly stakeholder updates ensure visibility. QA includes unit and integration tests, end‑to‑end smoke tests for critical flows, CI security scanning, and manual QA when needed. Releases use pre‑release and post‑deploy checklists plus an incident/rollback playbook to reduce risk.
